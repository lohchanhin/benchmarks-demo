## 已实施机制

产品分支加入文件元数据、哈希与解析复用；完整代次索引发布；单请求索引复用；
常驻 MCP 快照；按需导航；统一检索决定与踩坑记录。旧接口、四种模式保留。
独立导航实验配置仅暴露 lookup、open、memory search；记忆配置仅暴露记忆检索。
没有覆盖本机全局设置，也没有在产品代码加入目标仓库专用规则。

性能脚本为每次尝试创建新目录并保留所有观测。公开合成规模固定为 1,000 和
10,000 个 TypeScript 文件；VVE 只复制到本地临时目录做性能诊断，不恢复盲测资格。
路径、限定符号、普通符号、词法、一跳关系、记忆、未命中，共七种查询；每种分别
在 CLI 与常驻 MCP 上测 30 次热查询，严格顺序执行。
冷建设、进程启动、无变化重建、单文件变化刷新分别报告。
私有路径与源码只留在 `.benchmark-runs/`，不推送。

先 build 产品，再执行：

```powershell
node scripts/net-benefit-performance.mjs --product="D:\path\vertex-palace" --output=".benchmark-runs/net-benefit-v1/attempt-01" --vve="D:\path\private-project"
node --test test/net-benefit.test.mjs
```

合成数据生成器公开。性能测试的历史记录也是合成数据，不能证明真实记忆收益。

## 去留判定

排程函数要求工程通过、候选包哈希、12 个任务、4 个合格仓库以及早于修复的历史。
24 个“任务 × 索引状态”区块平衡分配六种 ABC 顺序，总计 72 次。
按独立任务汇总，不把重复次数当作独立样本。
成本包括 Agent 墙钟时间及未计入该区间的索引、记忆维护成本，不重复计算。
缺失 usage 仍为未知，失败和超时不补跑。

目前没有选取正式目标，也没有冻结用于 Agent 实验的候选包。
功能测试通过不等于工程闸门通过；性能结果与最终闸门状态会另行记录，
不改动已冻结协议，也不覆盖失败尝试。
