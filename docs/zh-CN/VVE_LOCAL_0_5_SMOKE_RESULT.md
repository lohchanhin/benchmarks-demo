# VVE 本机 0.5 历史任务冒烟结果

## 结论

**本轮完成，但属于负面结果：没有观察到候选版优势。**

这是在一个大型多租户 monorepo 上进行的本机、非盲测历史任务诊断。比较对象为候选提交 `2b87acd` 与公开 npm `0.4.0`。公开证据已移除仓库身份、绝对路径、任务符号和源码内容。

## 方法

- 候选版与基线复用同一份刷新后的 Palace 索引。
- 两个条件顺序执行，没有同时运行。
- 自然语言任务不提供文件、类、方法或函数身份。
- 精确身份任务提供真实实现身份和聚焦测试路径。
- 以历史提交的四种 changed-file 角色计分：后端模型、后端服务、聚焦测试和管理前端。
- 每个条件与任务形态只运行一次 warm Context；时间只能描述，不能推断稳定差异。

## 结果

| 任务形态 | 条件 | 覆盖率 | Focus | Context Token | Context 时间 |
| --- | --- | ---: | ---: | ---: | ---: |
| 自然语言 | npm 0.4.0 | 25% | 11.1% | 4,699 | 70.074 秒 |
| 自然语言 | 候选版 | 25% | 11.1% | 4,699 | 70.929 秒 |
| 精确身份 | npm 0.4.0 | 100% | 40.0% | 4,613 | 71.176 秒 |
| 精确身份 | 候选版 | 100% | 40.0% | 4,717 | 101.990 秒 |

同一种任务形态下，两版产生的标准化路线摘要完全相同。因此，这次候选版没有带来路由收益，也没有 Token 或时间收益；精确身份条件反而多出 104 个估算 Token，并在这一次观察中更慢。

## 原理层发现

1. 当任务没有可导航的文件、类、方法或函数身份时，自然语言路由仍然很弱。
2. 加入精确身份后，两版都明显改善，但公开基线已经达到完整 changed-file 覆盖，所以候选版没有新增价值。
3. 候选版的顶层 selection 报告 `sufficient`，最终 route closure 却仍是 `insufficient`，并缺少两个明确符号。这是通用的合同执行顺序矛盾，不能用 VVE 专用规则修补。
4. warm Context 约 70 秒，不符合交互式工具预期。单次候选版较慢不能证明稳定退化，但已经足以说明没有正向速度证据。

## 研究边界

VVE 目标从现在起永久关闭产品调参资格。下一次产品修改必须先用中性 fixture 复现证据状态矛盾，或完成 Context 分阶段性能剖析。本轮不能让 0.5 通过，也不支持更新 npm。
