The user authorized a ten-working-day investment decision, not an open-ended
routing optimization campaign. Implementation starts on 2026-09-09; the
engineering deadline is 2026-09-15 and the decision deadline is 2026-09-22 in
Asia/Kuala_Lumpur. No background scheduling is implied.

The [protocol](../../protocol/net-benefit-v1/protocol.json) fixes 12 fresh tasks,
three conditions and two index states: at most 72 sequential Agent executions,
15 minutes each, without replacement runs. Candidate and targets are deliberately
empty until engineering qualification. Historical targets cannot qualify again.

All conditions receive identical historical facts. Ordinary Markdown is the
baseline; memory search and on-demand navigation are separate additions.
Behavior and explicit constraints determine success, not agreement with a
historical patch's exact file list. Unknown usage remains unknown.

Engineering work: monotone evidence status, cached parsing, coherent index
snapshots, advisory lookup, and sourced memory search. Product APIs and existing
four modes remain compatible. The experimental plugin will be isolated.

Stages: baseline; evidence and indexing; lightweight APIs and engineering gate;
candidate freeze and fresh target selection; Agent study; retention decision.
Each stage publishes bilingual notes and sanitized machine evidence. Failure or
incomplete evidence at the deadline stops this campaign; npm latest remains 0.4.0.

Status: baseline frozen; no candidate frozen; no Agent executions.
